Python · Machine Learning · Robotics · Simulation

프로젝트 개요

선행 연구를 기반으로 한 로봇 구조를 실제로 제작하기 전에, 머신러닝을 활용해 이동 안정성과 경로 제어를 시뮬레이션 환경에서 먼저 최적화하는 과제연구 프로젝트입니다. 실제 하드웨어 제작은 시뮬레이션에서 안정적인 제어 조건이 확보된 이후 진행할 예정입니다.

접근 방식

  • 시뮬레이션 우선 검증 — 하드웨어 제작 전, 시뮬레이션에서 이동 패턴과 제어 안정성을 사전에 검증

  • 안정적인 이동 조건 탐색 — 다양한 환경 조건에서 강건하게 작동하는 제어 파라미터 발견

진행 상황

현재 시뮬레이션 환경에서 다양한 이동 패턴에 대한 검증을 진행하고 있으며, 이후 실제 물리 로봇에 적용해 sim-to-real gap을 확인할 예정입니다.

N진 탐색 알고리즘의 효율성과 하드웨어 상관관계 분석

Algorithms · Number Theory · Hardware · Optimization

탐구 동기

이진 탐색을 일반화한 n진 탐색 구조를 수학적으로 분석하고, 실제 하드웨어 환경에서 어떤 방식이 가장 효율적인지 탐구한 프로젝트입니다. 단순히 "이진 탐색이 좋다"는 결과가 아니라, 왜 그런가를 수학과 하드웨어 양쪽에서 설명하고자 했습니다.

1. 수학적 모델링

n진 탐색의 총 비교 횟수를 f(n) = (n−1)/ln n으로 모델링. 미분을 통해 이론적 최적값이 자연상수 e (≈ 2.718)임을 도출했습니다. 정수론적 한계로 인해 실제 후보는 n=2와 n=3이 됩니다.

2. 이론 vs 실제: 왜 n=2가 표준인가

  • 탐색 — n=3은 트리 깊이는 줄지만 추가 비교 연산이 필요하고, 비트 시프트(>> 1) 연산을 활용할 수 없어 하드웨어적 손실이 더 큽니다.
  • 정렬 — Java의 dual-pivot quicksort (n=3) 사례를 분석. 대용량 데이터에서는 n=3이 비교 횟수 약 10% 감소 + 캐시 적중률 최적화로 이득을 봅니다.

3. 도출한 통찰

알고리즘의 효율은 단순히 '수학적 연산량'만으로 결정되지 않습니다. CPU 연산 구조(비트 연산)와 메모리 계층(캐시)과의 정합성이 함께 작용합니다. 최적의 알고리즘은 정해진 것이 아니라 데이터의 특성(중복도, 크기)과 시스템 환경을 함께 고려해 유연하게 선택해야 합니다.

핵심 흐름

이론(수학) → 검증(구현/실험) → 통찰(하드웨어 이해)

학교 건물 최단경로 안내 시스템

Python · Dijkstra · Graph · Pathfinding

문제 인식

학교 건물 구조가 복잡해 학생들이 길을 자주 헤매는 문제가 있었습니다. 단순한 안내도로는 해결하기 어려운 상황 (비, 경유지 등)이 많아, 직접 알고리즘 기반의 안내 시스템을 만들어 보기로 했습니다.

구현 방식

  • 그래프 모델링 — 학교 건물 내부를 노드와 엣지로 모델링. 각 엣지에 이동 시간/실내·실외 정보 등 속성 부여
  • Dijkstra 알고리즘 — 가중치 기반 최단 경로 탐색
  • 날씨 옵션 — 비가 올 때 실내 경로를 우선적으로 탐색하는 모드 제공
  • 경유지 설정 — 특정 장소를 반드시 거치는 경로 탐색 기능

배운 점

교과서적인 알고리즘을 실제 환경에 매핑할 때 발생하는 디테일들 — 엣지에 어떤 가중치를 부여할 것인지, 사용자 의도(비, 경유)를 어떻게 그래프 탐색에 녹일 것인지 — 이런 모델링 과정이 알고리즘 그 자체만큼이나 중요하다는 것을 느꼈습니다.

광화문 도로 통제 사회적 손해비용 EDA

Pandas · NumPy · EDA · Public Data · Cost-Benefit Analysis

탐구 동기

2026년 3월 광화문 도로 통제가 시행되면서, 보도에서는 "교통 정체가 심각하다"는 정성적인 평가만 다뤄졌습니다. 그래서 "실제로 얼마나 큰 사회적 손해가 발생했는가"를 공공데이터를 활용해 정량적으로 추정해 보기로 했습니다. 단순한 정체 수치를 넘어, KOTI 교통혼잡비용 모델을 응용해 시간손실·차량운행비·연료비·사고비용·환경비용으로 분해 산정하는 것이 목표였습니다.

데이터 및 방법론

  • 활용 데이터 — 서울 열린데이터광장의 공공데이터 4종: 교통량, 통행속도, 버스 노선, 승하차 인원
  • 분석 설계 — 대조군(3.13~15) vs 실험군(3.20~22)으로 비교하는 quasi-experimental 방식
  • 비용 분해 — KOTI 교통혼잡비용 모델을 응용해 시간손실·차량운행비·연료비·사고비용·환경비용으로 분해 산정
  • 분석 단위 — 4개 주요 도로(세종대로, 사직로, 종로, 율곡로) × 시간대별로 세분화

주요 결과

  • 실험기간 3일간 측정된 직접 손해비용 약 1.5억 원 (차량 통행 손실 기준)
  • 분석 범위를 넓혀 버스 우회 · 도심 광역 정체 · 물류 지연까지 포함 시 약 12 ~ 21억 원으로 추정
  • 4개 도로 평균 속도 차이는 −3.7%에 불과 → 평균만 보면 영향이 작아 보임
  • 그러나 세종대로 새벽 02시만 보면 −20.5%의 큰 저하가 확인됨

인사이트

  • 평균은 진실을 가린다 — 전체 평균으로 보면 영향이 작아 보이지만, 시간대와 도로를 좁혀서 보면 큰 변화가 드러납니다. 데이터 분석에서 분석 단위의 선택이 결과의 의미를 좌우한다는 점을 체감했습니다.
  • 영향은 광장 본선에 집중 — 세종대로·사직로는 속도가 크게 저하된 반면, 종로·율곡로는 우회로 역할을 하며 오히려 속도가 증가했습니다. 도로망 차원에서 부하가 어떻게 재분배되는지 관찰할 수 있었습니다.
  • 데이터의 한계를 인정해야 함 — 직접 측정값(1.5억 원)과 종합 추정치(12~21억 원)의 10배 격차가 있었습니다. 공공데이터로 잡히는 손해는 빙산의 일각이라는 점, 그리고 정확한 단일 숫자보다 범위로 답하는 정직함이 필요하다는 점을 배웠습니다.

배운 점

이론적으로 완벽한 분석보다 "상황에 맞는 효율적 해법"을 선택하는 감각이 중요하다는 것을 배웠습니다. 또한 숫자만 던지는 것이 아니라, 숫자 너머의 맥락 — 왜 평균이 작은지, 왜 직접비와 추정치가 다른지 — 까지 함께 전달하는 인사이트의 중요성을 느꼈습니다. 분석가의 역할은 결과를 계산하는 것이 아니라, 결과를 의미 있게 해석하고 전달하는 것임을 체득한 프로젝트였습니다.

프로젝트 개요

구현 내용

  • 센서 데이터 처리 — IMU 센서에서 손목의 각도(Roll/Pitch) 데이터를 실시간으로 수집
  • 제어 신호 변환 — 손 각도 → 드론 제어 명령으로 매핑하는 변환 로직 구현
  • 실시간 통신 — 손 컨트롤러와 드론 간 무선 통신 구조 설계
  • 안정화 — 센서 잡음 필터링 및 데드존 설정으로 떨림 보정

배운 점

센서 데이터가 실제 하드웨어 제어로 연결되는 전체 파이프라인을 직접 경험할 수 있었습니다. 특히 raw 센서값을 그대로 쓰면 안 되고, 필터링과 매핑 함수를 거쳐야 비로소 의도한 제어가 가능하다는 점을 체득했습니다.

기숙사 자동 소등기

Arduino · RTC Module · Relay Circuit · IoT

문제 인식

기숙사 생활 중 불을 끄지 않고 자버리는 일이 잦았습니다. 매일 같은 시각에 자동으로 불이 꺼지는 장치가 있으면 좋겠다는 생각으로 직접 만들어 보기로 했습니다.

구현 내용

  • RTC 기반 시간 제어 — 설정된 소등 시간(오전 1시)이 되면 자동으로 조명을 끄도록 구현
  • 릴레이 회로 — 릴레이 회로를 이용해 실제 전등 전원을 직접 제어
  • 저비용 설계 — 단가를 줄이기 위해 저렴한 RTC 모듈 사용

예상치 못한 문제와 해결

저렴한 RTC 모듈을 사용했더니 예상보다 시간 오차가 컸습니다. 단순히 부품 탓을 하기보다, 오차를 직접 측정하고 보정값을 코드에 적용하는 방식으로 해결했습니다. 며칠간 오차를 기록한 뒤 일정한 drift를 발견해, 이를 보정하는 로직을 추가했습니다.

배운 점

부품의 한계를 코드로 보완할 수 있다는 점, 그리고 작은 일상의 불편을 직접 해결하는 즐거움을 경험했습니다.

아두이노 리듬게임기

Arduino · Real-time Processing · Embedded · Game

프로젝트 개요

버튼 입력과 LED 출력을 이용한 리듬게임 시스템을 하드웨어부터 직접 제작하는 프로젝트입니다. 기성 게임기를 사는 것이 아니라, 입력 판정·점수 계산·노트 시퀀싱·실시간 출력을 모두 직접 구현하고 있습니다.

주요 구성 요소

  • 입력 시스템 — 다중 버튼 입력을 동시에 처리하는 폴링 기반 입력 핸들러
  • 판정 로직 — 노트 타이밍과 입력 시점의 차이를 측정하는 정확도 판정
  • 점수 시스템 — 콤보, 정확도 등급, 보너스 점수 처리
  • 노트 시퀀싱 — 시간 기반 노트 데이터 구조와 출력 스케줄링
  • LED 출력 — 노트 등장과 입력 피드백을 실시간으로 시각화

현재 고민하고 있는 것

일반 프로그램과 달리 입력 지연(latency)과 타이밍 정확도가 사용자 경험을 결정합니다. millis()와 micros()의 사용 시점, 폴링 주기, 인터럽트 활용 등 실시간 처리 구조에 대해 많이 고민하게 되는 프로젝트입니다.

N차원 회전 행렬 시각화 프로젝트

Python · Linear Algebra · Visualization · Vibe Coding

탐구 동기

선형대수학에서 다루는 회전 행렬을 단순 계산이 아니라 실제 좌표계가 어떻게 변하는지 시각적으로 이해하고 싶었습니다. 특히 3차원을 넘어선 고차원에서의 회전이 직관적으로 어떻게 작용하는지 궁금했습니다.

구현 내용

  • 임의 차원 회전 행렬 생성 — n차원 공간에서의 회전 행렬을 동적으로 생성
  • 회전 평면 선택 — 어떤 2차원 평면에서 회전을 일으킬지 사용자가 직접 선택 가능
  • 실시간 시각화 — 회전 과정을 애니메이션으로 확인할 수 있도록 구성
  • 고차원 → 저차원 투영 — 시각화를 위해 고차원 점들을 어떻게 화면에 투영할지 직접 설계

배운 점

행렬을 단순한 숫자 덩어리가 아니라, 공간을 어떻게 변환하는 연산자로 이해하게 되었습니다. 특히 고차원에서는 회전이 "축"이 아니라 "평면" 단위로 일어난다는 점을 시각적으로 체득할 수 있었습니다. 이 경험은 이후 기하지능 연구에서 자코비안과 위상 분석을 직관적으로 이해하는 데도 큰 도움이 되었습니다.

신경망 표현 공간의 위상적 왜곡과 일반화 한계 분석

Topology · Differential Geometry · Deep Learning Theory · Representation Learning

핵심 가설

"신경망의 보간(interpolation) 메커니즘은 본질적으로 매끄러운 채움(smooth filling)이며, 이는 호모토피적으로 자명한 채움만을 생성할 수 있다. 따라서 비자명한 위상 구조를 가진 데이터의 합성적 일반화는 원리적으로 실패한다."

지금까지 한 것

  • 선행연구 분석 — Dupont et al. (Augmented Neural ODEs), Moor et al. (Topological Autoencoders), Naitzat et al. (Topology of Deep NNs) 3개 핵심 논문을 정밀 비교해 본 연구가 인과 메커니즘을 직접 제안하는 점에서 차별화됨을 확인.
  • Theorem 1 정식화 — Topological Collapse under Smooth Latent Interpolation. 잠재공간 차원이 데이터의 위상적 차원 미만일 때 디코더 야코비안의 rank collapse가 필연적으로 발생함을 수식으로 진술.
  • Toy 실험 6개 완료 — 3D Trefoil knot을 오토인코더로 압축·재구성하며 위상 붕괴 임계 차원 식별 (latent dim ≥ 3에서 보존, 미만에서 붕괴). Writhe 왜곡 +75.6%로 정량화.
  • 임계값의 본질 검증 — 3D 입력과 10D ambient(zero-padding)에서 동일한 임계 차원(dim=3) 확인. 임계값은 입력 차원이 아닌 데이터의 위상적 차원에 의해 결정됨.
  • Jacobian 특이점 분석 — dim=2(붕괴)에서 condition number 평균 6.52, dim=3(보존)에서 1.71. Theorem 1이 예측한 collapse signal(t*)을 실험적으로 확인.
  • 위상적 정규화 손실 대조 실험 — 실험 전 수립한 5개 예측이 5/5 모두 적중. 동시에 MSE가 2000배 증가하는 fundamental trade-off도 확인.

계획 중인 것

  • Theorem 1의 rigorous proof — 현재는 strong conjecture + empirical evidence 단계. 호모토피 이론(π₁, Whitney embedding theorem)을 바탕으로 한 엄밀한 수학적 증명으로 발전.
  • 실제 AI 벤치마크로 확장 — toy setting에서 SCAN, COGS, CFQ, 소형 Transformer로 확대. 위상 붕괴 신호와 합성 일반화 실패 간 상관관계 검증.
  • 측정 도구 정교화 — holonomy 기반 진단(이론) ↔ Jacobian SVD · TDA(실용)의 양방향 정렬.

악성 코드 위치 찾기

30개 서버 중 1개에 악성코드가 있고 잠복기 1시간의 분석기 5개로 단 1회 만에 찾아야 하는 상황. 5개 분석기를 이진법 5자리에 매핑해 소멸한 분석기 패턴으로 위치를 즉시 특정. (32개까지도 동일 전략으로 해결 가능.)

참고: The 1,000 Wine Bottles Puzzle
동적 프로그래밍

2-Eggs Problem — 임계 전압 최소 테스트

1~100MV 사이 임계 전압을, 깨지면 끝인 저항기 2개로 최소 횟수에 찾는 문제. 1+2+…+N ≥ 100에서 N=14가 최솟값임을 도출하는 점진적 간격 전략.

참고: 2-Eggs Problem
창의적 문제 해결 · 불변량

어두운 방의 동전

앞면 10개·뒷면 90개로 놓인 동전을 어두운 방에서 섞은 뒤, 10개를 추출해 양쪽의 앞면 수를 같게 만드는 방법. 정답은 추출한 10개를 전부 뒤집기 — x ↔ 10−x 대칭성의 발견이 핵심.

참고: 100 Coins in a Dark Room
정보 상식

Tupper's 자기언급 공식 — 17의 의미

"자기 자신을 그리는 함수"로 유명한 Tupper's formula에서 17의 의미를 묻는 문제. 정답은 비트맵의 높이 — mod(y, 17) 연산이 출력 비트맵의 세로 길이를 17픽셀로 제한.

참고: Tupper's self-referential formula

배운 점

좋은 문제는 단순히 어려운 문제가 아니라, "어떤 사고 단계를 거치면 자연스럽게 풀리는가"를 설계하는 일이었습니다. 출제자는 응시자보다 더 정확하게 알고리즘을 이해해야 한다는 점도 절감했습니다.

아두이노 입문 강연 — 사고뭉치(사뭉) 동아리

Arduino · Education · Public Speaking

강연 개요

교내 아두이노 동아리 '사고뭉치(사뭉)'에서 신입생 약 50명을 대상으로 아두이노 입문 강연을 진행했습니다. "처음 배우는 사람의 시선"을 유지하면서, 단순 문법 나열이 아니라 왜 이런 도구가 필요한지부터 직접 회로를 켤 수 있는 단계까지 자연스럽게 끌고 가는 강의를 목표로 했습니다.

강의 구성

  • 아두이노란? — 마이크로컨트롤러 보드 개념, 하드웨어/소프트웨어 통합 환경 소개
  • 회로의 기본 — 브레드보드 사용법, 저항·LED·점퍼선 활용
  • 아두이노 IDE — 코드 작성, 보드 업로드, 시리얼 모니터 사용
  • 핵심 함수 — pinMode, digitalWrite, digitalRead, delay, analogRead
  • 실습 예제 — LED 점등, 버튼 입력, 가변저항, 시리얼 통신
  • 응용 프로젝트 아이디어 — 센서를 활용한 자동화 시스템 예시

강의 방식

단순 문법 설명보다, 실제 하드웨어와 코드가 어떻게 연결되는지를 직관적으로 이해시키는 데 집중했습니다. 실습 위주로 구성해, 청중이 강의 시간 안에 직접 LED를 켜고 버튼 입력을 받아보도록 했습니다.

배운 점

가르치는 입장이 되어 보니, 내가 안다고 생각했던 것과 설명할 수 있는 것이 다르다는 것을 절감했습니다. 개념을 다른 사람의 언어로 다시 정리하면서, 오히려 제가 더 명확하게 이해하게 되는 경험이었습니다.
